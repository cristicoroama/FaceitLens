What these numbers can't tell you. Every chart above counts a column that is written once and never changed, so the daily figures are exact. The two things you asked about that are not here — how many times people signed in, and how many searches were run — can't be recovered: last_login and last_searched are overwritten in place, so only the most recent one survives. Counting those needs a small append-only table with one row per event.

Traffic is counted server-side, from API calls. That gives honest visitor and request numbers, but not which page someone was on: the browser sends only the origin as the referrer on cross-origin API calls, so /p/<nickname> and the leaderboard are indistinguishable from here. Per-page numbers, referrers and countries would need a script on the frontend instead.
